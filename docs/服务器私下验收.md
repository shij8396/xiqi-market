# 小内存服务器的私下验收

本配置用于没有备案域名时的服务器验收，不开放公网网站入口。默认使用 MySQL 8.4、Node 24 应用镜像和 Caddy 内部 TLS，数据库和应用均不发布宿主机端口，网关仅绑定 `127.0.0.1:8443`。

## 前提

- Linux x86_64、Docker 和 Compose 2；建议至少 2GB 内存。1GB 实例仅适合小规模验收，需预留 Swap 并观察实际内存和容器重启。
- 将项目放到服务器的专用目录。本次从本机上传源码和镜像，服务器无需访问 GitHub 或 Docker Hub。
- 在项目根目录创建权限为 600 的 `.env.private`，填写随机的 `DB_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`SESSION_SECRET`。不要复制已有本机演示数据库。
- `compose.private.yml` 使用 `xiqi-market:server20261006` 镜像；换镜像版本时需同步修改这个标签。

## 构建及导入

在可联网的电脑上构建 Linux amd64 镜像，导出应用、MySQL 和 Caddy 镜像，再上传服务器：

```bash
docker build --platform linux/amd64 -t xiqi-market:server20261006 .
docker pull --platform linux/amd64 mysql:8.4
docker pull --platform linux/amd64 caddy:2
docker save -o xiqi-market-images.tar xiqi-market:server20261006 mysql:8.4 caddy:2
```

服务器导入并启动：

```bash
sudo docker load -i xiqi-market-images.tar
sudo docker compose --env-file .env.private -f deploy/compose.private.yml up -d --pull never
```

应用自动初始化新数据库，但不创建演示账号。使用 `scripts/create-admin.js` 单独创建随机密码的管理员，避免在命令行参数或截图中暴露密码。容器与卷启用持久化和服务自动重启。

## 访问

在自己的电脑建立 SSH 隧道，私钥文件只保存在自己的电脑上：

```bash
ssh -N -L 127.0.0.1:8443:127.0.0.1:8443 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -i /path/to/private-key admin@SERVER_IP
```

打开 `https://localhost:8443`。Caddy 使用内部 CA，浏览器可能提示证书不受信任；这不是已签发的公网证书。使用内部 CA 证书验证自动化验收请求，不要关闭应用的 Secure Cookie。隧道关闭后本机不能访问，但服务器上的服务仍然运行。

Windows 本机可运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/connect-server.ps1 -ServerAddress SERVER_IP`；默认使用本机 `.runtime` 中的对应服务器专用私钥，支持通过参数指定用户名和私钥路径。脚本优先绑定 WLAN 地址以避免本机 VPN 干扰这条 SSH 连接，不修改全局路由或代理设置。

## 手动备份

在服务器项目目录运行 `bash scripts/backup-server.sh`，会将一致性数据库快照和上传文件分别保存到权限受限的 `backups` 目录，并检查压缩包完整性。脚本不安排定时任务，也不替代恢复演练；正式运营需将备份复制到独立存储并验证恢复。

## 边界

- `DEMO_MODE=false`，未配置短信服务时注册、找回密码不可用；未配置微信服务时微信登录不可用。
- 这套配置不开放公网访问。上海服务器的公开网站需准备可备案域名、完成备案并配置公开 HTTPS 后，另行切换生产入口。
- 上线前仍需进行备份恢复验证、真实短信验收、容量测试与运行监控；Swap 不代表服务器容量足够承载正式流量。
- 不执行 `docker compose down -v`，否则会删除数据库与上传文件卷。
